## 〇、环境与版本矩阵（联调前每人对照自查）

| 组件 | 版本要求 | 说明 |
|------|---------|------|
| JDK | **21（Temurin）** | 以 backend/pom.xml 为准；IDEA 项目 SDK 选 Temurin 21 |
| Maven | **3.6+** | 配阿里云镜像；依赖版本只认 pom.xml，禁止手改 |
| Node.js | **22 LTS（最低 20）** | 前端构建用 |
| npm | 10+ | 源统一 npmmirror：`npm config set registry https://registry.npmmirror.com` |

- 前端依赖版本以 `frontend/package.json` + lockfile 为唯一来源，禁止手删 lockfile 重装。
- **敏感配置（数据库密码、API Key）一律放 `application-local.yml` / `.env`（已进 .gitignore 不入库）**；仓库内只提交 `.example` 模板，各人复制改名后填写。

## 一、Git 协作规范

### 1.1 分支与权限
| 分支 | 用途   | 谁能推 |
|---|-----|---|
| `main` | 主干，应保持可运行、可部署    | 仅组长合入 |
| `feature/*` | 功能分支，从 `main` 派生 | 各开发成员 |
| `docs/*` | 文档、语料等非代码提交   | 全员         |

- 严禁直接向 `main` 推送，改动一律走 PR（Pull Request）。
- 例：前端队友 A 开发登录页 → `git checkout -b feature/login`。

### 1.2 提交信息（Conventional Commits）
格式：`类型(范围): 描述`
```
feat(rag): 接入 DeepSeek RAG 检索
fix(tts): 修复流式分句拼接丢失问题
docs(readme): 补充部署说明
chore: 初始化项目结构
style(eslint): 收紧引号规则
```
惯用类型：`feat` 新功能 / `fix` 修 bug / `docs` 文档 / `style` 格式 / `refactor` 重构 / `test` 测试 / `chore` 杂项。

### 1.3 提交规则
- 一次提交只做一件事，粒度小而完整。
- 提交前自查：无 `console.log` 泄漏、无密钥（`.env` 一律不入库）、无大二进制。
- 拉取代码前先 `git pull`，以减少冲突。

## 二、后端规范（参照阿里巴巴 Java 开发手册）

### 2.1 分层与包结构
```
com.scenic.digitalhuman
 ├─ controller/   // 只做参数接收与响应包装，不含业务逻辑
 ├─ service/      // 业务逻辑
 ├─ mapper/       // 数据访问（MyBatis-Plus，脚手架已引入 3.5.12）
 ├─ entity/       // 与数据库表对应的实体
 ├─ dto/          // 接口入参/出参对象
 ├─ config/       // 配置类
 └─ util/         // 静态工具
```

### 2.2 命名
- 类名：大驼峰 `UserController`；方法/变量：小驼峰 `getUserById`
- 常量：全大写下划线 `MAX_RETRY`
- 表名：下划线小写 `scenic_spot`；字段：下划线小写 `create_time`
- 布尔命名：`isXxx`；集合：复数名词 `userList`

### 2.3 注释（配合 IDEA 模板）
- 每个类、方法必须有 Javadoc 头注释（作者/日期/描述），模板见课件 PDF 第九~十三页。
- 方法必写：`@param`、`@return`、`@Description`。

### 2.4 硬性红线（阿里手册要点）
- 禁止魔法值：数字/字符串必须定义常量或枚举。
- 统一返回：所有接口返回统一响应体 `Result<T>`（code/message/data）。
- 禁止 `System.out.println`，一律用 slf4j 日志。
- 异常必须有处理：不裸抛，定义业务异常 + 全局异常处理器。
- 禁止在循环内做数据库查询（N+1）；批量操作用批量 SQL。

### 2.5 工具卡点
- IDEA 安装 **Alibaba Java Coding Guidelines** 插件，开启实时监测。
- 提交前源码须通过插件扫描，清理 Blocker/Critical 级问题。

## 三、前端规范（参照 ESLint 配置说明）

### 3.1 工具
- 项目内启用 **ESLint**，通过 `npm run lint` 校验，`--fix` 自动修复格式问题。

### 3.2 核心规则（从课件附录裁剪，可后续补充）
| 规则 | 要求 |
|---|---|
| `no-unused-vars` | 禁止声明后未使用的变量（error） |
| `quotes` | 字符串统一双引号（error） |
| `semi` | 语句必须分号结尾（error） |
| `camelcase` | 命名强制驼峰（error） |
| `eqeqeq` | 必须使用全等 `===`（error） |
| `no-console` | 禁止 `console.log`（warn，上线前清理） |
| `indent` | 4 空格缩进（error） |

> 完整规则表见配置说明，前期按需启用，随开发补充。

### 3.3 组件与样式
- 组件命名：PascalCase 单文件组件 `VisitorPanel.vue`。
- UI 组件库**待引入 Element Plus**（引入时机由前端负责人定，引入后本条生效：统一走组件库，不手写重复样式）。
- 接口请求统一封装 axios 实例，禁止散落裸请求。

## 四、文档与目录规范

### 4.1 目录约束
| 目录 | 放什么 |
|---|---|
| `docs/` | 规范、接口契约、设计文档 |
| `backend/` | 后端源码 |
| `frontend/` | 前端源码 |
| `deploy/` | Docker Compose 及部署脚本 |
| `mysql/` | 数据库初始化脚本 |

### 4.2 交付物规范
1. 系统功能分析说明书 → `docs/`
2. 系统接口设计文档 → `docs/`（接口契约先冻结再编码）
3. 系统详细设计 → `docs/`
4. 系统安装部署文档（含 docker 镜像） → `deploy/`
5. 系统操作说明书 → `docs/`
6. 系统源文件及说明 → 对应源码目录 + README
7. 数据库脚本文件 → `mysql/`

### 4.3 语料 / 测试集
- 语料统一放 `docs/语料/` 下的结构化 markdown，按景区/主题命名。
- 内部评测集按"游客会问的问题"格式出题，`docs/评测集/`。
